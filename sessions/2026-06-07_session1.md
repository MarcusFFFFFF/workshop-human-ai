## Avvikelser och designbeslut

### 1. Source-filter — spec-bugg flaggad och löst

Specen säger: *"hämta poster med source som börjar med `workshop-` (matchar `workshop-agi-out` OCH `workshop-code-out`)"*.

Problemet: `source_contains="workshop-"` i `memory_core.search` är SQL LIKE `%workshop-%` — den matchar även `workshop-marcus` (inbound). Resultat skulle bli ekoloop där varje inkommande meddelande postas tillbaka till Telegram som "outbound".

Lösning i koden: `source_contains="workshop-"` + post-filter `src.endswith("-out")`. Detta matchar `workshop-agi-out` och `workshop-code-out` (samt eventuella framtida `workshop-X-out`), men exkluderar `workshop-marcus`.

Tabell:

| source | matchar prefix? | matchar `-out`? | skickas? |
|---|---|---|---|
| `workshop-marcus` | ja | nej | nej |
| `workshop-agi-out` | ja | ja | ja |
| `workshop-code-out` | ja | ja | ja |
| `claude-outbound` | nej | (irr.) | nej (v6:s domän) |
| `thread-agi-out` | nej | (irr.) | nej |

Detta är säkrare än specen och förlorar inga giltiga out-poster. Marcus kan invända om konventionen `workshop-*-out` är fel — då justerar jag.

### 2. State-filer i workshop-mappen

v6 lägger `.telegram_offset` och `.sent_outbound_ids` i cwd. Jag valde absoluta paths under `Path(__file__).parent`:

- `~/workshop-human-ai/.workshop_telegram_offset`
- `~/workshop-human-ai/.workshop_sent_outbound_ids`

Skäl: (a) håller staten där bridgen bor oavsett varifrån den startas, (b) undviker kollision med v6:s state-filer om bridgen någonsin körs från samma cwd som v6. Prefixet `.workshop_` gör tydligt vilken bridge som äger filen.

### 3. Default chat-id som fallback

Spec: chat-id läses från env `WORKSHOP_CHAT_ID` (förmodligen samma som privat). Jag lade in `DEFAULT_CHAT_ID = "7063134958"` som fallback om env är osatt. Det är samma som v6 hårdkodar. Om Marcus vill att bridgen ska vägra starta utan explicit env kan vi ändra det till hård krav.

### 4. Wake-mekanism oförändrad från v6

Samma AppleScript-sekvens (activate Claude → `.` → Enter). Sänder bara wake när nya inbound-meddelanden upptäcks, inte vid outbound. Konsekvens: outbound från Code/AGI-tråd till Marcus väcker inte Claude Desktop — Marcus ser dem i Telegram. Detta speglar v6.

### 5. Observatörspingar AV (per spec)

Ingen ANTHROPIC_API_KEY läses, ingen modellanrop-kod kvar.

### 6. Initial test-meddelande

`[workshop_bridge] Startad. AGI-tråd + Code kan nu nås via denna lina.` — analogt v6:s startup-ping.

## Block 2 — (G) Code-wake-mekanism implementerad

**Bakgrund:** Code saknade wake-mekanism. AGI väcks via AppleScript-keystroke i Claude Desktop (etablerat mönster i ping_loop_v6). Code lever i terminal-harness där samma keystroke-trick inte är rätt verktyg.

**Vägval (G):** File-watcher snubbeltråd + harness wake-on-bg-exit. Marcus visade att han kört mönstret framgångsrikt i annan Claude Code-tråd. Avfärdade alternativ:
- (D) `claude -p` per event — cold context, ny betalmodell från 2026-06-15
- (E) Officiella Channels (research preview) — kräver Bun + plugin, byter ut bridge-arkitektur, oprövat hos Marcus
- (F) iMessage-channel — bryter symmetri med AGI:s Telegram-setup

(G) vann på: redan prövat, minimal ny ytarea, hederligast F-9/F-12-mässigt (modellerar explicit att Code är vilande mellan turer).

**Tillagt:**
- `tools/recall.py` — wrapper för `memory_core.search`
- `tools/post_code_out.py` — skriv post med source `workshop-code-out`
- `tools/read_workshop_thread.py` — kronologisk läsning av workshop-* (SQLite direkt, eftersom memory_core.search är similarity-rankad)
- `tools/wait.sh` — snubbeltråd som blockar på `.code_wake` mtime-ändring; exit triggerar harness-wake. 3s poll, 1h timeout-safety.

**Ändrat i `workshop_bridge.py`:**
- Konstant `CODE_WAKE_FILE = SCRIPT_DIR / ".code_wake"`
- Ny funktion `touch_code_wake()` — bumpar mtime explicit via `os.utime` (touch utan args uppdaterar inte mtime om filen finns)
- Anropas parallellt med `wake_claude_desktop()` när nya inbound upptäcks. AGI och Code väcks alltså samtidigt.

**Symmetri-not:** AGI och Code har olika wake-mekanik (AppleScript vs bg-job-exit) eftersom plattformarna är olika. Strukturellt symmetriskt: vardera instansen vilande tills extern trigger. Brevlådan (memory_core) och kanalen (workshop-bot) gemensam.
